## 1. 产品目标

将 Flutter 移动端的视觉与交互从"自研主题（当前 `main.dart` 为 `colorSchemeSeed: Colors.teal` 的 Material3 默认色）"重构为与网页端 **逐像素 1:1 对齐**——覆盖导航范式、设计 token、三类主题（default 亮 / default 暗 / liquid 玻璃），并提供"登录即同步、离线优先"的记账体验，使手机端用户获得与网页端一致的视觉与操作心智。

---

## 2. 用户故事

1. **作为老用户**：登录 Flutter 后首屏自动拉取我在网页端已有的全部账本与流水，无需任何手动操作。
2. **作为用户**：我在 Flutter 看到的账本列表、账本详情、统计、搜索与网页端视觉一致（同一套色板 / 圆角 / 间距 / 字号）。
3. **作为用户**：我可以在 **亮色 / 暗色 / 液态玻璃** 三套主题间切换，且三套在移动端表现与网页端一一对应。
4. **作为用户**：我在无网时记的账本地保存，联网后自动同步到服务端并被其他端可见（离线优先）。
5. **作为用户**：我使用与网页端一致的"**首页列表 + 左上回首页 + 右上外观按钮**"导航，没有移动端独有的底部 Tab 或错位元素。
6. **作为用户**：我能调整字号三档缩放，放大后布局仍可读、不溢出。

## 5. 验收标准（如何判定"1:1 还原"）

### 5.1 视觉 / 布局验收

- **色值 hex 对齐**：移动端色值必须等于网页端设计 token（ink 灰阶、`#ff2d87`、emerald、red、amber），以 Ardot 设计稿 `712589903280969` 为唯一基准；不得残留 `Colors.teal` 等自研色。
- **布局结构一致**：页面区块顺序、卡片结构、列表项结构、间距与圆角与网页端一致；允许移动端必要的响应式收拢，但**不得引入网页端没有的元素**。
- **导航范式一致**：无底部 Tab；首页列表为根；详情页左上"回首页"；右上"外观浮动按钮"。
- **字号缩放可读**：三档缩放下无文字截断 / 溢出，断点与网页端一致。
- **三主题视觉一致**：default 亮、default 暗、liquid 玻璃在移动端与网页端三主题一一对应。
- **无"未对齐"残留**：彻底移除 `AppColors / AppTheme / AppCard` 自研主题与 teal 配色残留。

### 5.2 同步验收（诉求 1：登录后自动同步已有数据）

> 同步引擎已存在（`SyncService.syncAll` 先推后拉），本次只定义验收边界，不设计新架构。以下以实际代码现状为据。

| 验收项 | 标准 | 现状（代码核对） |
|---|---|---|
| 登录后首屏触发 | 进入首页即 `syncAll`（先推后拉），拉取网页端已有数据 | ✅ 已实现：`HomePage.initState` → `load()` + `sync()` |
| 防重复拉取 | 并发 / 重复触发安全，不重复全量拉取 | ✅ 已实现：`_syncing` 守卫，`syncAll` 重复返回 `false` |
| 登录失效处理 | `unauthorized` 清空会话并回到登录页 | ⚠️ 部分：`syncAll` 捕获 `unauthorized` → `clearSession()`；需确认 `RootSwitcher` 据此重建回登录页 |
| **服务端软删下发** | 服务端软删（`deletedAt`）的账本/条目，拉取后应从移动端**移除或标记删除** | ❌ **缺口**：当前 `_pullAll` 仅按 `serverId` `insert`/`upsert` 存在行，**不删除本地多余行**；服务端软删的记录在移动端仍可见 → 列为验收红线，需补齐 |
| 离线优先 | 写先落本地再 `enqueue`；联网 `drainQueue` 重放；未同步本地行不被覆盖 | ✅ 已实现：乐观更新 + 待同步队列；`pullAll` 仅覆盖有 `serverId` 的行 |
| 软删一致性 | 移动端本地删除也应进入待同步队列，服务端软删生效 | 需与网页端软删口径对齐（5 个模型 `deletedAt`，聚合须 `NOT_DELETED`） |

> 红线说明：**"服务端软删未下发"是当前最大对齐缺口**，必须在 P0/P1 内补齐（拉取后比对 `serverId` 集合，清理本地已不存在且已同步的行），否则移动端会长期显示网页端已删数据。
